# JunLive v1.2.2

**修复斗鱼画质列表 —— 按房间真实档位展示，不再虚标「原画」。**

---

## 🐛 修复的问题

在斗鱼房间里选「原画」，实际播出来却是**蓝光4M**；而且画质列表里出现多个**内容相同**的条目。

### 根因

斗鱼接口的返回里其实**明确写着实际给了哪一档**，我们却没有读它：

```json
// 请求 rate=0（原画）时，斗鱼实际返回：
{
  "rate": 4,                              ← 实际给的是 rate=4（蓝光4M）
  "rtmp_live": ".../138243rxRx2mY3Pe_4000.flv",   ← _4000 = 4M 流
  "multirates": [
    {"name": "原画1080P60", "rate": 0, "bit": 15254},
    {"name": "蓝光8M",     "rate": 8, "bit": 8000},
    {"name": "蓝光4M",     "rate": 4, "bit": 4000},
    {"name": "超清",       "rate": 3, "bit": 2000},
    {"name": "高清",       "rate": 2, "bit": 900}
  ]
}
```

旧逻辑**无条件把第一条标成「原画」**，于是：

- UI 上写着「原画」，播的却是 4M
- 「原画 / 蓝光8M / 蓝光4M」三条**指向同一个流**，列表里三个重复条目

### 修复后

逐档请求后，**以接口返回的 `data.rate` 为准**取名，并按实际档位去重。

**实测对比**（同一批在播房间）：

| 房间 | 修复前 | 修复后 |
|---|---|---|
| 138243 洞主 | 原画 / 蓝光8M / 蓝光4M / 超清 / 高清（后三条重复） | **蓝光4M / 超清 / 高清** |
| 7592343 一只三吃 | 原画 / 蓝光8M / 蓝光4M / 超清 / 高清 | **原画2K60 / 高清** |
| 558004 子丘 | 原画 / … | **原画1080P30** |

**每个房间的画质档位本来就不同**，现在展示的就是该房间真实可用的档位。档位名也直接采用斗鱼给的名字（`原画2K60` / `原画1080P60`），比写死的「原画」更有信息量。

## 📌 关于「有些房间没有原画」

这不是 bug，是斗鱼的**服务端房间级策略**。

请求 `rate=0`（原画）时，斗鱼可能直接回 `data.rate=4`（蓝光4M），同时返回的 `eticket` 为 `null` —— 表示**没有授权高码率档**。拿到原画时则是**无码率后缀的源码流**且 `eticket` 有值。

已验证**与客户端参数无关**，以下手段全部无效：

| 尝试 | 结果 |
|---|---|
| 更换 `did`（设备 ID） | 无效 |
| `hevc=1`（H.265 编码） | 无效 |
| 依次切换 3 条 CDN 线路 | 无效 |
| 改用 `getH5Play` 端点 + `ver` / `iar` 参数 | 鉴权失败（该端点不认当前签名方式） |

签名与请求方式与成熟工具 streamlink 的斗鱼实现一致。真正的开关是 `eticket`，由斗鱼按房间/账号下发。

**当前做法：能拿到就列出原画，拿不到就不列，显示真实档位 —— 不假装。**

## ⚠️ 已知限制

- **APK 未签名** —— 只能侧载，不能上架应用商店
- **iOS 暂不出包** —— 需要 Mac 构建环境与开发者账号
- **斗鱼高码率档（原画/蓝光8M）在部分房间不可用** —— 服务端按房间下发 `eticket`，客户端无法绕过
- **Twitch 走代理时抖动大** —— 详见 v1.2.1 说明，建议换延迟稳定的节点或使用清晰度上限选 720p
- **安卓全屏时系统状态栏仍会显示** —— 属 Tauri 能力边界
