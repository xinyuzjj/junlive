# JunLive v1.2.3

**四项修复：斗鱼播放不再卡顿、油管不再把回放当直播、缓冲按平台区分、安装包不再缺文件。**

---

## 🐛 ① 斗鱼每 5 分钟卡一下 —— 已修

### 现象

斗鱼看到第 5 分钟左右会卡住、显示「缓冲中」，然后自己恢复，循环往复。

### 根因

斗鱼的 FLV 直链**每 300 秒被 CDN 主动切断**（服务端策略，与网络无关），必须重新取地址续流。而旧实现有两个问题：

**问题一：新连接建立在关键路径上**

```
旧流断开 → 解析地址 → DNS + TCP + TLS → 拿到首块数据
           ↑ 这 1.8 秒里播放器什么都收不到
```

**问题二：要求关键帧「必须严格超前」**

换 CDN 节点后新流常比旧流慢一点（实测约 1.5 秒），它的关键帧落在已转发位置**之后一点点**。旧逻辑只接受严格超前的关键帧，于是只能**再等一个 GOP**（约 1.5 秒）。

### 修复

**1. 提前建连 + 预缓冲**（提前 8 秒）

```
旧流断开 → 数据已经在内存缓冲里，直接接上
```

**2. 允许关键帧小幅回退**（容忍度 2.5 秒）

播放器本身落后转发位置 6~12 秒，这点重叠落在**还没播到的区间**，MSE 直接覆盖，不会重复播放。

### 实测

| 版本 | 续流空档 |
|---|---|
| 修复前 | **1799 ms** |
| 只做预取连接 | **1525 ms**（全花在等关键帧） |
| **本轮修复** | **309 ms** |

实测 380 秒播放，进度全程连续，**无一次停滞**。

## 🐛 ② 油管：不在直播就不播回放

### 现象

关注里的油管主播已经下播了，列表还显示「在播」，点进去播的是一段录像。

### 根因（两层）

**后端判断字段用错**

```jsonc
// 已结束的直播，实测三个字段：
"isLiveContent": true,    // ← 旧代码用它判断，含义是「曾经是直播」，结束后永远为真
"isLive": null,           //   直播时才是 true
"isLiveNow": false,       //   最干净，直播/回放都明确给值
```

**前端无条件渲染播放器**

油管的 iframe 地址是**直接用路由里的视频 ID 拼的**，而且不管是否在直播都会渲染 —— 后端早就说了「未开播」，前端照播不误。

### 修复（三层）

| 层 | 改动 |
|---|---|
| 后端判断 | `isLiveContent` → **`isLiveNow` / `isLive`** |
| 后端兜底 | 视频不在直播时，**再查一次这个频道现在有没有在播**，跟到当前这一场 |
| 前端渲染 | **只在确实在直播时**才渲染播放器；iframe 用**后端解析后**的视频 ID，不用路由参数 |

### 实测

| 场景 | 结果 |
|---|---|
| 正在直播 | 2 个 iframe（播放器 + 官方聊天），无提示 |
| 已结束的直播 | **0 个 iframe**，显示「该主播当前未开播」 |
| **关注里存的旧视频 ID**（频道正在播） | 自动跳到频道**当前这一场** |
| 直接粘频道 ID | 解析出当前直播 |
| 未开播的频道 | 「该频道当前未开播」 |

## ⚡ ③ 缓冲按平台区分 —— 不再误伤其他平台

上一版为了修 Twitch / 斗鱼的卡顿把缓冲调大了，但**写成了全局配置**，导致所有平台都白白多了几秒到几十秒延迟。

现在按「这个平台到底需不需要」分开：

| 平台 | 容器 | 缓冲 | 为什么 |
|---|---|---|---|
| **斗鱼** | FLV | **6~12 秒** | 每 300 秒续流，必须留缓冲 |
| 虎牙 | FLV | 1~3 秒 | 直链不会被周期性切断，不需要 |
| **Twitch** | HLS | **8~60 秒** | 必须走代理，实测代理延迟抖动 84ms → 1891ms |
| SOOP | HLS | 同 Twitch | 海外，走代理 |
| B站 / 抖音 | HLS | 3~15 秒 | 国内直连，延迟本来就稳 |

### 实测

```
斗鱼  缓冲 7.3s     ← 需要
虎牙  缓冲 1.0s     ← 不再被误伤
B站   缓冲 2.1s     ← 不再被误伤
```

## 🔧 ④ 安装包装完起不来 —— 已修

### 现象

用 `setup.exe` 装完，双击启动弹出：

> junlive.exe - 系统错误
> 由于找不到 WebView2Loader.dll，无法继续执行代码。

### 根因

本项目用 **GNU 工具链**，无法静态链接 WebView2 的 MSVC 静态库，所以 `junlive.exe` 变成**动态依赖** `WebView2Loader.dll`。而 Tauri 打包时：

| 打包类型 | 是否带上 DLL |
|---|---|
| MSI | ✅ 带了 |
| **NSIS `setup.exe`** | ❌ **没带** |

### 修复

把 DLL 固定进项目并声明为打包资源：

```json
"bundle": {
  "resources": { "webview2/WebView2Loader.dll": "WebView2Loader.dll" }
}
```

### 实测

静默装到临时目录 → 目录里有 `WebView2Loader.dll`（160,880 字节）→ 实际启动成功（窗口标题 `JunLive`）→ 卸载清理。

## ⚠️ 已知限制

- **APK 未签名** —— 只能侧载，不能上架应用商店
- **iOS 暂不出包** —— 需要 Mac 构建环境与开发者账号
- **斗鱼高码率档（原画 / 蓝光8M）在部分房间不可用** —— 服务端按房间下发 `eticket`，客户端无法绕过；拿不到时列表里就不显示原画，不虚标
- **Twitch 走代理时抖动大** —— 已用大缓冲缓解，根治要靠更稳定的代理节点
- **YouTube 需要 Cookie** —— 代理 IP 会被判为机器人，需在「设置」里粘贴 Cookie
- **安卓全屏时系统状态栏仍会显示** —— 属 Tauri 能力边界
